# 唐诗三百首规范内容源

`tang_poems_final.json` 是从归档资料构建的规范内容总表，`poems/index.json` 与 `poems/*.json` 是同步拆分的单诗文件。网页和 iOS 使用从这里生成的 `../reader/` 产品数据。

## 来源与重建

- `../../唐诗三百首.json`：原有 317 首基础资料，保留原样。
- `../raw_sources/`、`../sources/ctext_clean.json`：原始网页和结构清洗结果；提供书序、正文、繁体及英文资料，保留原样。
- `../sources/chiuinan_clean.json`：补充注释及校勘对照。
- `../sources/tang300_new_dedup.json`：补充标签。
- `../content-corrections.json`：显式的补收、序文分离、正文与元数据修订规则，每项修订记录原文、依据和来源。

在项目根目录运行（需要 OpenCC 与 pypinyin）：

```sh
python3 scripts/build_final_source.py
python3 scripts/split_final_poems.py
python3 scripts/validate_final_source.py
```

构建不覆盖归档来源、编辑释义或插画策划。当前 320 首覆盖 CText 书序 1–320；补入原基础资料缺少的 043《长干行》、134《送李中丞归汉阳别业》、278《宫词》。原 317 首的 ID 和书序保持不变。

## 内容字段

`schemaVersion` 为 `1.1.0`。每首诗保留稳定 `id`、原书 `order`、体裁 `section`、标题、作者、别名、简繁正文及来源关系，并将不同性质的文字分开：

- `lines` / `linesTraditional`：正文段落；客户端按句中标点继续分为完整诗句。
- `text` / `textTraditional`：正文拼接，不含序文或校勘尾注。
- `preface` / `prefaceTraditional`：独立的散文序数组；全库 6 篇，界面展开时再阅读。
- `variants`：原选本尾部“又作”说明，保留简繁原行、来源和 URL。旧 17 首与新增《长干行》共 18 首有此类尾注。来源未标明对应字句的，不推断替换位置。
- `corrections`：正文修订及依据，包括《玉台体》缺字恢复和核对后的录入讹误；原文仍可追溯。
- `metadataCorrections`：标题、作者等元数据修订及依据；《阙题》的“刘脊虚”修为本地基础源的“刘昚虚”，第 108 首标题的“问道归凤翔”据核本修为“间道归凤翔”。标题修订不改变原有 ID。
- `notes`：带来源的归档注释，保持来源文字；分组、去重与页面释义由产品层完成。
- `rubyLines`：完整正文字符与历史拼音数据，当前界面不展示拼音。
- `displayLines` / `displayRubyLines`：旧短行预览字段，不能代替长诗全文。
- `english`：归档英文原文及轻清洗版本，空格缺失问题尚在，不作为产品译文。
- `sourceRefs`：基础来源、选本匹配、注释、标签来源与置信信息；补收的 3 首明确标记 `base.supplemented`。
- `visual`：可选的旧视觉策划字段。当前实际插图由产品层选图，不以这个字段判断覆盖率。

合法异文和作者归属差异不机械统一。例如《在狱咏蝉》的“客思侵／深”、《琵琶行》的泉流句异文以及《渡汉江》的作者归属，仍依当前选本保存。基础原始文件不因规范层校订而改写。

## 校验范围

`content_audit.json` 记录全库结构校验及 213 首固定体裁（五绝、七绝、五律、七律）的句数、汉字数。校验会把正文修订逆向还原，并加回序文、异文，确保 320 首的简繁原始选本文字可完整重建；还检查单诗文件与总表一致。

《贼退示官吏并序》《观公孙大娘弟子舞剑器行并序》《石鱼湖上醉歌并序》《琵琶行并序》《燕歌行并序》《在狱咏蝉并序》的序文均已单独保存。《在狱咏蝉》正文恢复为 8 个五言句。

全库比较了规范正文与基础资料的差异，确认的 22 处正文问题及 2 处元数据问题按校勘记录修复，共涉及 21 首；字形、异文和版本归属差异保留。第 179 首题名的“留春”经核对原书保留，不作误录删除。结构检查并不等同于逐字版本学定本，古体与乐府也不强制套用律绝的句数规则。
