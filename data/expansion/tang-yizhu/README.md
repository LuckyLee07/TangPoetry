## 收集范围与方法

1. 以作者、题名建立独立选目，覆盖初唐、盛唐、中唐、晚唐常见诗人及部分女诗人。包含山水、田园、边塞、送别、咏物、咏史、讽谕等不同写作内容；这些是选目方向，尚未作为逐篇已验证标签写入。
2. 从开放仓库的 57,607 条唐诗来源记录中定位选目，留存实际选中的 1,146 条原始记录。没有把整部《全唐诗》复制到项目中。
3. 同名组诗逐首保存；《宫词一百首》等大组诗仅收选定部分。合并同篇不同版本时，保存见证正文、来源和差异，不直接丢弃异文。
4. 用《千家诗》对应篇目、该书 4 个公开试读篇目及另外 9 个古诗页面补充对照。没有匹配结果的篇目不会凭记忆填入。
5. 与 `data/final/tang_poems_final.json` 按作者、原文、异题比较。正文比较使用去标点、简体及少量异体字折叠；显示文本仍保留底本读法。
6. 字数、句数、初步体裁和指纹由脚本计算。无法可靠确认的创作时间、地点、译文、拼音等字段置空。

## 体裁与文本的重要限制

- `form.proposedGenre` 是**初分**。四句五言、八句七言等形状不能单独证明绝句或律诗的格律身份；未逐篇验平仄、用韵，`prosodyVerified` 一律为 `false`。
- 底本明确带乐府门类时记录为乐府；乐府是来源类别，可以同时具备五言、七言或杂言的句式。不要将 `proposedGenre` 与 `metricalShape` 当成互斥学术分类。
- 简体正文经 OpenCC 转换；繁体正文尽量保留底本。对于只有简体的补充来源，繁体是机器转换，并明确标为 `OpenCC-s2t-generated-not-edition`。
- 来源中的 `[欸]`、`[昭]` 等补字保留正文中的字，并存下编辑标记；脚注编号和括号内说明移入 `sourceAnnotations`。跨段注释也会处理，原始来源始终保留。
- 《全唐诗》转录数据并非无误定本。有些字形、题名、归属及补遗诗仍需核对；例如《画鹰》的私用区编码已明确隔离，不能直接进入生产数据。
- 作者资料保存的是仓库所录小传。这里没有把小传拆成未经核验的生卒年、出生地等“确定事实”。唐末五代跨期作者须进一步逐篇确定时代。
- `new-candidate` 只说明“不重复、未触发当前明确疑点规则”，不是“内容已经审校无误”。

## 离线重建与检查

在项目根目录运行，Python 3.10+；依赖项目已有的 `opencc-python-reimplemented`（本次使用 0.1.7）。

```bash
python3 scripts/build_tang_yizhu.py
python3 tests/tang_yizhu_data_test.py -v
```

重建只读取本目录留存的来源和当前 App 诗库，不联网、不覆盖正式内容。若正式诗库变化，需重建后更新本说明的统计数字。

校验覆盖：唯一 ID、全文哈希、字数句数、原始记录无遗漏、见证来源、作者与组诗引用、候选与已收篇目分离、书目确认范围、选目待核状态、补字保留及跨段注释等。通过结构校验不等于完成文学版本校勘。

增加新选目时，先补充 `sources/` 的可核实来源，再调整脚本或映射并重建；不要直接手改生成的 `poems.json`。完整来源导入模式还支持 `--import-corpus`、`--authors`、`--qianjiashi`，其中整库输入须含 `sourceFile`、`sourceIndex`，正常离线重建不需要整库。
